# 0009. 운동 기록 = 회원 자산 (스키마 · SOP · 권한 · AI · 권리)

- **상태**: Accepted
- **결정일**: 2026-05-20
- **결정자**: Young
- **선행**: [ADR 0001](./0001-consumer-pivot.html), [ADR 0007](./0007-trainer-model.html)

## 맥락 (Context)

기존 1:1 PT 산업의 핵심 약점:

- 회원은 강사를 옮기면 운동 이력이 사라진다.
- 강사가 회원 데이터를 갖고 있을 뿐 (수첩·엑셀·기억).
- 다른 강사가 회원 상태를 모름 → 매번 0에서 다시 시작.

본 플랫폼은 [ADR 0001](./0001-consumer-pivot.html) 의 "강사·종목·시간 매번 자유 선택" 모델로 회원이 여러 강사를 거치는 게 정상이다. 이 모델에서 **운동 기록이 회원에게 귀속되지 않으면 회원이 매번 0에서 시작** → 모델 자체가 작동 ❌.

따라서 **운동 기록 = 회원 자산** 이라는 데이터 권리 원칙을 봉인한다. 이는 동시에 **데이터 플라이휠** (강사 기록 → 회원 이력 → AI 개인화 → 회원 retention → 강사 등급 KPI) 의 입력 단이 된다.

## 결정 (Decision)

### 1. 운동 기록 스키마 (필수 항목)

세션 1건당 기록되는 표준 필드:

| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| `session_id` | uuid | ✅ | 세션 PK |
| `member_id` | uuid | ✅ | 회원 |
| `mentor_id` | uuid | ✅ | 진행 강사 |
| `started_at` / `ended_at` | timestamp | ✅ | 30분 unit 단위 |
| `program_category` | enum | ✅ | 1:1 PT · 스트레칭 · 필라테스 · 요가 ... |
| `exercises[]` | jsonb | ✅ | 종목 배열 (아래 §1.1) |
| `intensity_rpe` | int (1~10) | ✅ | 회원 자가 평가 RPE |
| `posture_notes` | text | 선택 | 강사 자세 코멘트 (자유 텍스트) |
| `pain_report` | jsonb | 선택 | 부위·강도·메모 |
| `condition_score` | int (1~5) | ✅ | 회원 컨디션 자가 평가 |
| `mentor_notes` | text | 선택 | 강사 메모 (회원 공개) |
| `mentor_private_notes` | text | 선택 | 강사 비공개 (다음 강사도 비공개) — §3 권한 |

#### 1.1 `exercises[]` 세부

```json
[
  {
    "name": "스쿼트",
    "category": "lower_body",
    "sets": [
      { "weight_kg": 40, "reps": 12, "rpe": 7 },
      { "weight_kg": 50, "reps": 10, "rpe": 8 },
      { "weight_kg": 50, "reps": 8,  "rpe": 9 }
    ]
  }
]
```

- 종목 마스터 (`Exercise`) 는 본사 관리 (admin) 카탈로그.
- 부위 분류 (`category`) — 상체·하체·코어·풀바디·유산소·재활·기타.

### 2. 입력 SOP (Standard Operating Procedure)

- **강사가 모바일 앱에서 5분 내 입력 완료** 가능한 UX 가 1순위.
- 입력 시점: **세션 종료 직후 ~ 24시간 이내**.
- 누락 시: 24시간 후 강사 앱 푸시 알림 · 48시간 후 등급 KPI `입력률` 에 -1 카운트.
- **입력률 ≥ 90%** = 강사 등급 P2+ 임계 ([ADR 0007 §4](./0007-trainer-model.html)).
- 회원도 본인 앱에서 직접 추가 메모 가능 (선택).

### 3. 권한 (Access Control)

| 주체 | 접근 권한 |
|---|---|
| 회원 (본인) | ✅ 전체 열람 · 정정 · export · 삭제 권리 |
| 본인 세션을 진행한 강사 | ✅ 본인이 기록한 세션 + 다른 강사의 회원 공개 기록 (mentor_notes 까지) |
| 다른 강사 (이 회원의 다음 세션 예정) | 회원 동의 시 열람 (예약 시 1-tap 동의 토글, 디폴트 ✅) |
| 본사 (admin) | 익명화 집계만 (개인 식별자 마스킹) |
| 외부 (보험사·의료기관 등) | ❌ (회원이 직접 export 후 본인 책임 공유) |

- `mentor_private_notes` 는 작성한 강사 본인만. 다른 강사·회원·본사 ❌. (강사 내부 메모 공간)
- 회원이 강사 차단 시 해당 강사 → 그 회원 기록 접근 즉시 차단.

### 4. AI 활용 (Phase별)

| Phase | 데이터 누적 | AI 역할 |
|---|---|---|
| **Phase 1** (~D+90) | 회원당 세션 ≤ 30 | 단순 이력 조회 — "지난주 스쿼트 50kg × 10" 같은 조회 응답 |
| **Phase 2** (~D+180) | 회원당 세션 30~100 | 종목 추천 — "오늘은 하체가 어제 강했으니 상체 추천" |
| **Phase 3** (D+180~365) | 회원당 세션 ≥ 100 | 정체 감지 — 중량·반복수·RPE 정체 시 강사에게 알림 |
| **Phase 4** (D+365+) | 부위별 빈도·부상 데이터 누적 | 부상 예방 — 불균형·과사용 패턴 감지 후 강사에게 알림 |

- AI 는 **강사 보조 도구** — 운동 처방 ❌ ([ADR 0002 §4](./0002-license-policy.html) 호칭 안전판 + 자격증법 회피).
- AI 출력은 강사에게 먼저 표시 → 강사가 회원에게 적용 여부 결정.

### 5. 회원 권리 (GDPR / 한국 개인정보보호법 정합)

| 권리 | 구현 |
|---|---|
| **열람** | 회원 앱 "내 기록" 화면 — 전체 세션 타임라인 |
| **정정** | 본인 자가 입력 항목 (RPE·컨디션·메모) 직접 수정. 강사 입력 항목은 강사에게 요청 |
| **export** | PDF · CSV 다운로드 (개인정보보호법 §35-2 이동권) |
| **삭제** | 회원 탈퇴 시 90일 grace period 후 영구 삭제. 본사 익명화 집계 통계에는 비식별 누적치만 남김 |

## 검토한 대안 (Alternatives)

### 대안 A — 강사가 기록 소유 (기존 PT 산업 패턴)
- 장점: 강사 lock-in.
- 단점: 회원 자유 선택 모델 ([ADR 0001](./0001-consumer-pivot.html))과 정면 충돌. 데이터 플라이휠 ❌.
- **기각**.

### 대안 B — 본사가 기록 소유 (회원·강사 모두 단순 사용자)
- 장점: 데이터 통제 ↑.
- 단점: 회원 권리 침해, GDPR/개인정보보호법 위반 위험.
- 기각.

### 대안 C (채택) — 회원 자산 + 강사 입력 + 본사 익명화 집계
- 권한 계층화로 모든 주체 만족.
- 데이터 플라이휠 입력 단 명확.

## 결과 (Consequences)

### 긍정적

- **회원 retention** — 운동 이력이 따라오므로 강사 변경·다종목 시도가 자연스러움.
- **데이터 플라이휠** — 강사 입력 → 회원 이력 누적 → AI 개인화 → 회원 retention → 강사 등급 KPI.
- **법적 정합** — GDPR·개인정보보호법 회원 권리 (열람·정정·export·삭제) 완비.

### 부정적 / 리스크

- **강사 입력 부담** — 세션당 5분 추가. 완화: 모바일 UX 최적화·음성 입력·종목 마스터 자동완성.
- **입력률 ≥ 90% 임계 미달 강사 풀** — 등급 강등 위험. 완화: P1 신입은 입력 SOP 코칭 별도.
- **데이터 저장 비용** — 회원 1인당 연간 ~수십 MB (이미지·동영상 포함 시 ~수백 MB). 초기 부담 적음.
