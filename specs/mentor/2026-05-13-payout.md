# 💪 멘토 정산 (v2)

**Status**: v2 Accepted · **Layer**: 💪 멘토 · **Updated**: 2026-05-16
**관련 결정**: [ADR 0001](../../decisions/0001-consumer-pivot.html) · [ADR 0002](../../decisions/0002-license-policy.html) · [ADR 0004](../../decisions/0004-one-time-ticket-pricing.html)
**📡 API**: [catalog](../api/catalog.html) `/api/mentors/me/payouts/*`
**🗄️ Data**: [9. Payout](../data/09-payout.html)

## 1. 배경 (v2)

v2 정산은 **30분 unit 1세션 = 1 정산 단위**. 시나리오 두 가지 ([ADR 0001](../../decisions/0001-consumer-pivot.html) §6):

| 시나리오 | 단가 (30분/세션) | 자격증 | 베타 |
|---|---|---|---|
| **S1 — 파트타이머** (일반 멘토) | **12,000원** (예시) | ❌ (검증 코스만) | 위주 |
| **S2 — 전문 강사** (Pro) | **최대 20,000원 상한** | ✅ | 호점 확장 시 비중 ↑ |

Pro 옵션(회원 추가금 +5,000원/세션, [ADR 0004](../../decisions/0004-one-time-ticket-pricing.html))은 **멘토 100% 인센티브** — 본사·가맹점주 분배 ❌.

v1의 "90분 세트 분배 가설 (멘토 50% / 본사 30% / 가맹점주 20%)" 폐기.

## 2. 락된 규칙

- 정산 주기 = **격주 (2주)**
- 1 정산 단위 = **MentorBlock(30분 unit) status=completed**
- 60분 예약 = 2 unit = 2 정산 카운트
- 단가 = `admin.PayoutConfig.mentor_rate_general` (S1) / `admin.PayoutConfig.mentor_rate_pro_max` (S2 상한)
- Pro 옵션 추가금 = `admin.PricingConfig.pro_mentor_surcharge_per_session` × 멘토 100%

## 3. 산식

```
기본 정산 = (S1 멘토면) general_rate × completed_units
          + (S2 Pro 멘토면) pro_rate × completed_units   (pro_rate ≤ 20,000)
Pro 인센티브 = pro_surcharge × completed_units (Pro 강사만)
─────────────────────────────────────
멘토 격주 정산액 = (기본 정산 + Pro 인센티브) − 패널티 차감
```

패널티:
- 멘토 노쇼: 해당 unit 정산 차감 + 회원 보상 비용 1 회 회당가 차감
- 6h 이내 슬롯 취소: 해당 unit 정산 차감

## 6. 결제 → 정산 흐름

```
회원 결제 (회차권) → 본사 직수령
회원 예약 → MentorBlock assigned (회차 1 차감 + Pro 옵션 포인트 차감)
세션 완료 → MentorBlock status=completed
  → DistributionEntry 자동 생성 (mentorId·unit·rate·proSurcharge)
격주 cron `payout-calculate` → MentorPayout row 생성 + 입금 처리
```

## 7. Edge Cases

- 회원 회차권 환불 (사용 회차 차감 후): 이미 정산된 분 회수 ❌, 미래 정산에 영향만
- 본사·멘토 사유 노쇼: 회원 BonusCredit 1매 + 정산 차감
- 입금 실패: admin 재시도 (`POST /api/admin/payouts/:id/retry`)
- 단가 변경 (admin이 PayoutConfig 변경): 변경 이후 완료된 unit부터 적용 (소급 ❌)
