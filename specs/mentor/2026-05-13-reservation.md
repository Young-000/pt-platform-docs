# 💪 슬롯 오픈·매칭 (멘토 흐름)

**Status**: Draft
**관련 결정**: [3A 강사 페르소나](../../partners/personas.html) · [3E 운영 모델](../../partners/model.html) · [5A 예약](../../operations/reservation.html)

## 1. 멘토 시나리오

| 흐름 | 액션 |
|---|---|
| 슬롯 오픈 | 캘린더에서 가능 시간 30분 단위 토글 |
| 회원 매칭 (자동) | 회원 예약 들어옴 → 본인 슬롯 잡힘 → 일정 자동 추가 |
| 회원 거절 받음 | 매칭된 회원이 24h 내 거절 → 슬롯 다시 open으로 복귀 |
| 슬롯 변경 | 가능 시간 ON/OFF 토글 (48h 전까지) |
| 슬롯 취소 (긴급) | 본인 사정 — 6h 전까지 가능 (그 이후 패널티) |

## 2. 화면 요구사항

### 슬롯 캘린더
- 4주 보기 (오늘 ~ +28일)
- 30분 단위 그리드 (시간 × 요일)
- 클릭 → ON/OFF 토글
- 색상: open (회색) / 예약 잡힘 (파랑) / 진행 완료 (녹색) / 취소 (빨강)

### 매칭 알림
- 푸시: "이번 주 화 19:00 슬롯에 회원 X 매칭됨"
- 인앱: 회원 프로필 미리보기 (운동 이력·이전 멘토 여부)

### 슬롯 관리 (변경·취소)
- 변경: 48h 전까지 가능 (그 이후 = 운영 매니저 승인 필요)
- 취소: 6h 전까지 = 멘토 등급 패널티 ❌
- 6h 이내 취소 = 회원에게 회차 +1 보상, 멘토 등급 패널티 + 정산 차감

## 3. 매칭 우선순위 (멘토 측 자동 반영)

```
회원 예약 들어옴 → 이 슬롯이 그 회원의 이전 멘토인가?
  Yes → 이 멘토에게 우선 매칭
  No → AI가 가능 멘토 풀 중 추천
```

→ 멘토는 별도 액션 ❌. 시스템이 자동으로 처리.

## 4. 데이터 모델 (멘토 관점)

```
MentorBlock (멘토 30분 단위 가능 시간)
  ├─ id, mentor_id, start_at (30분 정각)
  ├─ status ENUM(open, assigned, completed, cancelled)
  ├─ assigned_session_id, assigned_at

MentorCancellation
  ├─ id, mentor_id, block_id, reason
  ├─ penalty_applied (bool), created_at
```

## 5. 다른 레이어 영향

- **👤 유저**: 회원이 본 매칭 화면 → [예약 PRD](../user/2026-05-13-reservation.html)
- **🏢 플랫폼**: 멘토 풀 + 매칭 알고리즘 + 패널티 시스템

## 6. 엣지 케이스

- 슬롯 오픈했는데 회원 예약 없음: 슬롯 만료 후 자동 close (멘토는 다른 일정 가능)
- 멘토가 같은 시간 두 방 cover 안 됨 (30분 stagger): 시스템이 자동 처리
- 멘토 노쇼 (6h 이내 취소 없이 미참): 등급 패널티 + 회원 회차 보상

## 7. 측정 지표

- 슬롯 오픈 → 매칭 비율 ≥ 70%
- 멘토 슬롯 안정성 (취소율) ≤ 5%
- 6h 이내 취소 ≤ 1%
