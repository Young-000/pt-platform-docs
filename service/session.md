# 4B. 클래스 포맷 (그룹 클래스 · 룸 배타)

**🟡 Updated (2026-06-04)** · 의존: [ADR 0011](../decisions/0011-recovergx-gx-pivot.html), [4A 클래스 종류](./session-types.html), [4D 공간](./space.html) → [5A 예약 시스템](../operations/reservation.html), [7A 단위 경제](../economics/unit-economics.html)

> **📌 GX 피벗 (2026-06-04)**
>
> 30분 unit / Smart Session(1:1 PT) → **그룹 클래스(정원 N, 기본 20)**. 룸당 시간당 1 클래스(배타). 강사가 시간·정원·가격 지정. 출석 체크(attended / no_show). 클래스 완료 시 정산.

## 클래스 구조

```
[그룹 클래스]
────────────────────────────────────────────────────
강사 개설: 지점 · 룸 · 카테고리 · 시간 · 정원(기본 20) · 가격
회원 예약: 지점 → 날짜 → 시간표 탐색(잔여석) → 드롭인
룸 점유:   해당 룸은 클래스 시작~종료까지 배타 (다른 클래스 동시 불가)
완료:      강사가 출석 체크(attended / no_show) → 클래스 완료 → 정산 트리거
```

## 운영 단위

| 단위 | 설명 | 비고 |
|---|---|---|
| 클래스 | 강사가 개설한 단일 GX 수업 | 시작~종료 룸 배타 |
| 정원 | 강사 지정 (기본 20명) | 잔여석 실시간 표시 |
| 가격 | 클래스마다 상이 (강사 지정, 어드민 상한/하한 범위 내) | 예: 스트레칭 15k · 버닝 30k |
| 출석 상태 | `attended` / `no_show` | 클래스 완료 전 강사 입력 |
| 정산 시점 | 클래스 완료 후 정산 정책 스냅샷 기준 | 정책 변경에도 과거 정산 불변 |

## 예약·취소·환불

| 이벤트 | 처리 |
|---|---|
| 예약 | 지갑에서 클래스 가격 차감, 좌석 확보 |
| 취소 (시작 6h 전) | 전액 환불 — 지갑 즉시 크레딧 (현금 아님) |
| 취소 (시작 6h 이내) | 환불 없음 (노쇼와 동일 처리). 좌석은 복구 |
| 노쇼 | 패널티 없음. 결제액 → 정산 매출 귀속 |
| 폐강 (강사/어드민) | 예약자 전원 전액 환불(지갑) + 좌석 복구 |

> `refundCutoffHours`(기본 6h)는 어드민 정책으로 조정 가능.

## 정산 (조합형)

```
강사 지급액 = 기본금 + (인당 금액 × 출석 인원) + (클래스 매출 × 비율%)
```

- 어드민이 세 요소를 자유 조합 (0으로 비활성 가능). 강사별 정책 할당.
- 클래스 완료 시 **정책 스냅샷**으로 정산 박제 → 이후 정책 변경에 영향받지 않음.
- 상세: [3G 정산](../partners/payout.html).

## 핵심 원칙

- **예약 대상 = 특정 클래스** (강사+시간+룸이 이미 묶여 있음). 회원은 클래스를 선택.
- **룸 배타** — 하나의 룸에 같은 시간에 2개 클래스 동시 개설 불가.
- 카테고리·가격 상한/하한은 어드민이 정의 ([4A 클래스 종류](./session-types.html)).
